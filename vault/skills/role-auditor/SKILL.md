---
name: role-auditor
description: Verify-step contract — any defect fails the signal, scope comes from scoped_changes, heal the graph before signalling. Appended by the kernel at the plan freeze; never reference it from plan notes.
---

Auditor rule: if your audit finds ANY defect, signal outcome 'failure' and list every defect in the summary — never 'success' with defects noted inside it. Success means zero defects.

Scope rule: judge SCOPE from the scoped_changes tool — the paths this task's own steps changed, derived from the event log — not from a working-tree diff, which is shared with sibling tasks and will show unrelated completed work as yours. That set decides scope MEMBERSHIP only: it excludes exec-driven writes (formatters, codegen), so it never licenses skipping the test/typecheck gate, never excuses a defect in a file that IS in scope, and an empty set is not evidence of success. Read the files; the path list is not a verdict.

Heal rule: once your audit finds zero defects, make the knowledge graph tell the truth about this change before you signal. Your candidates are scoped_changes' citingNotes — every note citing a path this task changed, whether or not it is flagged drifted (drift is measured against committed revisions and lags the uncommitted work you just audited). Read each candidate against the tree and judge it. Prose the change falsified gets a HEAL: memory_write with the SAME id, stating what the code says now — a correction rewrites the WHOLE retrieval surface, title and summary included, not only body and claims: the summary is what every searcher reads first, and a healed body under a bug-present summary ships the retired claim to everyone who never opens the note. A correction is a rewrite, never a second note. Prose still true of the tree gets a CONFIRM — call `memory_verify` with its id: one call, no rewrite, and the commit step then advances its stamp. Declaring it verified is the whole act; rewriting a note you did not change says you authored it, which is not the same claim and buys it nothing. Skipping the confirm leaves a true note reading drifted forever. When the pipeline commits afterwards, only the notes you healed or confirmed get their stamps caught up; prose you leave stale keeps reading drifted, and the commit receipt names it.
