# packages/kernel/src/kernel.ts

## Facts
- Kernel (packages/kernel/src/kernel.ts) is the single writer for task, plan, workspace and project-identity events, appending every event through EventLog transactions. {9pphnp9p @packages/kernel/src/kernel.ts#Kernel #architecture-current}
- Kernel.proposeSplit rejects a child plan draft that assigns role committer/finisher or reuses FINISH_STEP_ID/CHECKS_STEP_ID unless authoredBy equals SPLIT_ORIGIN.freeze, so only the kernel's own finalize_plan freeze can grant commit/finish privileges to a step. {4txv1lrd @packages/kernel/src/kernel.ts#Kernel.proposeSplit #architecture-current}

## Why
- Kernel.approvalDoors lists the author sources that satisfy the plan gate and comes from the config file, because widening it lets the driving agent approve plans it authored. {xojurbpg @packages/kernel/src/kernel.ts#Kernel}
- cancelSubtree stamps the whole subtree in one project-lock transaction, so a task_split lands either before the sweep (its child is cancelled too) or after commit (the terminal-parent guard refuses it) and no orphan child starts after the cancel. {0r08rbhi @packages/kernel/src/kernel.ts#Kernel.cancelSubtree}
- cancelSubtree appends its cancellations in the same transaction that reads the task states, so a run that finished meanwhile keeps its real terminal status instead of being recorded as cancelled. {2rmt0roz @packages/kernel/src/kernel.ts#Kernel.cancelSubtree}
- createGroundedTask applies the project's maxIterations to both template steps because every subplan inherits its parent step's budget, so a per-analyzer override alone would move nothing below the analyze step. {4kqc9ehy @packages/kernel/src/kernel.ts#Kernel.createGroundedTask}
- Kernel.createGroundedTask seeds a policy-auto-approved [analyze, plan] step template because the real human approval gate is the conversational approve inside the plan step, not this scaffold. {zd2we067 @packages/kernel/src/kernel.ts#Kernel.createGroundedTask #architecture-current}
- editPlan accepts a blocked task as well as awaiting_approval because a task that settled blocked holding a defective frozen plan would otherwise have no repair path but cancelling and discarding its completed steps. {efdyt6u3 @packages/kernel/src/kernel.ts#Kernel.editPlan}
- ensureWorkspace returns an existing record unchanged and discards the branch, onTrunk, kind and title it was passed, because a difference has two opposite readings and only the caller knows which; adoptCwd archives and re-adopts on a branch change. {a2c8jigq @packages/kernel/src/kernel.ts#Kernel.ensureWorkspace}
- ensureWorkspace's managed and baseBranch default to false and null because a directory orc merely walked into is not orc's to delete; only re-adoption holds the prior record those facts come from. {ptyp5ygg @packages/kernel/src/kernel.ts#Kernel.ensureWorkspace}
- nonHumanPlanApproval is a sibling read rather than a widened return on approvedPlanHash because approvedPlanHash is the gate and a refusal message must never be a reason to touch what satisfies it. {9lroip2v @packages/kernel/src/kernel.ts#Kernel.nonHumanPlanApproval}
- proposeSplit refuses a split under a cancelled, done or failed parent because cancel stamps the parent under the same project lock, so a late split would otherwise create an unattended auto-approved subtree the sweep never reaches. {ov61zmaa @packages/kernel/src/kernel.ts#Kernel.proposeSplit}
- proposeSplit reserves the finish and checks step ids alongside the committer and finisher roles because stepMayReconcile keys on both terms, and a split step named 'finish' would shadow the kernel's own in every id-keyed read. {suweqrnp @packages/kernel/src/kernel.ts#Kernel.proposeSplit}
- replyFeedback records the answerer's door as the author source because for a grounded task the conversational approval is the human gate, so the door decides whether a person or an agent driving MCP approved the plan. {uv5dhtjf @packages/kernel/src/kernel.ts#Kernel.replyFeedback}
- restoreWorkspace re-seats a workspace under its original id through the kernel rather than a raw append, because the no-two-active-records-per-cwd rule only holds when the check and the append share a transaction. {otyrq6up @packages/kernel/src/kernel.ts#Kernel.restoreWorkspace}
- workspaceCwdKey normalizes syntactically only and refuses an empty cwd, because two live records for one directory make workspaceByCwd answer the first minted and an empty path would resolve to the process's own directory. {wzt3srcy @packages/kernel/src/kernel.ts#workspaceCwdKey}
