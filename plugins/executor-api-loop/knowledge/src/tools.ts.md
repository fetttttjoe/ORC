# plugins/executor-api-loop/src/tools.ts

## Facts
- executeTool's claimWrite() calls assertInZone(workspaceDir, abs, guard.zone) before any write/delete, enforcing the step's declared zone write-fence globs, then eagerly registers the path in a module-level writeClaims Map keyed by workspaceDir+absolute path, refusing a write from a different runToken with a 'concurrent write refused' error. {7aey1afz @plugins/executor-api-loop/src/tools.ts#claimWrite #architecture-current}
- executor-api-loop's tools.ts calls assertInZone before every fs_write/fs_edit/fs_delete tool call resolves, so an out-of-zone write is refused at the moment the model attempts it, with a message naming the offending relative path and the declared zone. {i1mhv9d0 @plugins/executor-api-loop/src/tools.ts#claimWrite #fact}
- releaseWriteClaims(runToken) frees all write claims held by that runToken; loop.ts calls it in startTurn's finally block and before yielding a join_splits/ask_human suspension, so a suspended or ended turn never fences siblings out of a path it is not actively writing. {86aq7tcx @plugins/executor-api-loop/src/tools.ts#releaseWriteClaims @plugins/executor-api-loop/src/loop.ts #architecture-current}
- toolSet() omits fs_write, fs_edit, and fs_delete when the step role is STEP_ROLE.scout or ctx.step.readOnlySource is true, so scout and read-only-source steps cannot write files. {6gccyp9y @plugins/executor-api-loop/src/tools.ts#toolSet #architecture-current}
- toolSet() in plugins/executor-api-loop/src/tools.ts registers the built-in tools signal, fs_read, fs_write, fs_edit, fs_delete, fs_list, join_splits, and ask_human, declared without an `execute` function since execution happens separately in executeTool. {bn3m87tz @plugins/executor-api-loop/src/tools.ts#toolSet #architecture-current}
